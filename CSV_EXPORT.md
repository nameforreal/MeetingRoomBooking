# CSV-экспорт — этап 5.6.2

Оба интерфейса используют rooms.csv_export.export_bookings. Формат сохранён:
UTF-8, ровно один BOM в начале, разделитель `;`, русские заголовки, стандартное
экранирование csv.writer для кавычек, разделителей и переносов строк.
Django Admin сохраняет дополнительный столбец «Создано»; собственная панель —
прежние семь столбцов. Порядок: начало встречи, затем ID для одинакового времени.

Для сдачи добавлены явные параметры собственной панели: `room` (ID),
`date_from` и `date_to` (YYYY-MM-DD). Даты включительны по локальной дате начала
встречи в TIME_ZONE проекта. Список, ссылка экспорта и CSV используют одинаковые
фильтры; отсутствующие границы не ограничивают период. Неверная комната/дата или
обратный диапазон дают HTTP 400 вместо выгрузки всей базы. Django Admin сохраняет
фильтры комнаты и start_time/date hierarchy перед применением выбранных ID.

## Защита ячеек

Текст, начинающийся с `=`, `+`, `-`, `@`, нейтрализуется начальным апострофом.
Проверка учитывает ведущие пробелы, Unicode whitespace, управляющие символы и
U+FEFF перед формулой. Начальные tab/CR/LF также получают апостроф. Проверяются
все текстовые ячейки, включая имя пользователя, email и название комнаты.

Обычный текст, кириллица, пустые значения, кавычки, `;` и внутренние переносы
сохраняются. Изменяется только представление в экспорте, БД не обновляется.
При импорте в некоторых режимах табличного редактора апостроф может быть виден;
его нельзя удалять автоматической постобработкой с последующим вычислением
формул. CSV — не типизированный XLSX, и поведение импортёра остаётся частью
проверки совместимости. Прямое выполнение формул в Excel/LibreOffice тестами
не запускается; проверяются байты файла и безопасные значения после csv.reader.

## Фильтры и выбор

- `/management/export.csv` поддерживает только GET и общие со списком фильтры
  `q` и `status`: поиск по комнате, username и email. Пробелы, ограничение поиска
  в 100 символов и поведение неверного статуса совпадают. Ссылка передаёт
  URL-encoded поиск. Выгружается вся подходящая выборка, включая записи за
  пределами нынешнего ограничения списка в 300 строк; выбора отдельных строк
  в собственной панели нет. POST возвращает 405 для уполномоченного пользователя.
- Django Admin экспортирует пересечение явно выбранных ID с текущим поиском
  и фильтрами changelist. Пустой выбор не выгружает всё. `select_across` запрещён
  для этого действия с понятным сообщением: автоматическое расширение выбранных
  строк до всех результатов не допускается.

## Разрешения

Нужны активная учётная запись, is_staff и отдельное rooms.export_booking.
View/change_booking сами по себе не дают экспорт. Для Django Admin дополнительно
нужен обычный доступ к списку бронирований. В собственной панели export_booking
остаётся самостоятельным правом, как раньше. Группы и назначения не менялись.
Admin POST сохраняет CSRF-защиту и повторную проверку разрешения в обработчике.
Экспорт не меняет revision, бронирования, результаты ключей или AuditEvent.
