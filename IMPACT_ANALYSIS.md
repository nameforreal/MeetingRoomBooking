# Impact analysis — VIP-согласование и CSV-экспорт

Документ фиксирует затронутые модули и регрессионные проверки для двух обязательных изменений ИСП49.

## 1. VIP: ожидание подтверждения администратором

| Область | Затронутые модули | Изменение / риск |
|---|---|---|
| Модель и правила | `rooms/models.py`, `rooms/booking_rules.py` | Статусы `pending/confirmed/cancelled`, правила создания и переноса VIP-бронирования |
| Транзакции | `rooms/booking_operations.py`, `rooms/audit.py` | Согласование, отмена и перенос выполняются атомарно; revision и AuditEvent сохраняются вместе с операцией |
| API | `rooms/api.py`, `rooms/api_urls.py` | Создание/изменение/отмена и подтверждение защищены серверной валидацией; статус не принимается как доверенное поле от пользователя |
| Панель сотрудника и Admin | `management/views.py`, `rooms/admin.py`, `rooms/permissions.py` | Доступ к подтверждению/отклонению ограничен permissions |
| Интерфейс | `rooms/views.py`, `rooms/templates/rooms/` | Пользователь видит состояние ожидания и историю, сотрудник — доступные операции |

**Основные регрессии:** `rooms/test_vip.py`, `rooms/test_final_contracts.py`, `rooms/test_revision.py`, `rooms/test_idempotency.py`, `rooms/test_audit.py`, `rooms/test_permissions.py`, `rooms/test_concurrency.py`.

Проверяются создание обычной/VIP-брони, ожидание, подтверждение, отказ, отмена, повторная отправка, устаревшая revision, перенос между типами комнат, конкурентные операции и сохранность аудита.

## 2. CSV-экспорт с фильтрами по комнате и датам

| Область | Затронутые модули | Изменение / риск |
|---|---|---|
| Формирование файла | `rooms/csv_export.py` | Общий CSV writer, UTF-8 BOM, разделитель `; `, экранирование и защита от CSV formula injection |
| Фильтрация и панель | `management/views.py`, `rooms/views.py` | Фильтры комнаты, диапазона дат, поиска и статуса согласованы со списком бронирований |
| Django Admin | `rooms/admin.py` | Экспорт сохраняет применённые фильтры и разрешения |
| Доступ | `rooms/permissions.py` | Экспорт доступен только при наличии отдельного permission |
| Документация | `CSV_EXPORT.md`, `API_GUIDE.md` | Описаны параметры, формат, ограничения и безопасная обработка значений |

**Основные регрессии:** `rooms/test_csv_export.py`, `rooms/test_permissions.py`, `rooms/test_final_contracts.py`, `scripts/test_e2e_http.py`.

Проверяются фильтры room/date_from/date_to, неверные значения, пустой диапазон, права доступа, сохранение порядка, BOM/кодировка/разделитель и нейтрализация потенциальных формул. Содержимое БД при экспорте не изменяется.

## 3. Общая оценка влияния

- Существующие API-контракты, права доступа и история бронирований проверяются регрессионными тестами.
- Новые сценарии не обходят общий сервис транзакционных операций.
- Основные изменения покрыты unit/integration и HTTP E2E; PostgreSQL-тесты отдельно проверяют блокировки и ограничения.
- Полный список бизнес-ограничений и результаты прогонов — в `DELIVERY.md`; исходные правила — в `BUSINESS_RULES.md`.
